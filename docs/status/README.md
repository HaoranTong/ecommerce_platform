# 项目状态跟踪系统

本目录包含项目核心状态文档，支持当前工作跟踪和历史工作记录。

## 📋 核心文档结构

### 🤖 自动化文档 (禁止手工编辑)
- **[模块开发状态](module-status.md)** - 自动统计的模块完成情况、API端点、代码行数
  - 📊 **更新方式**: 执行 `tools/update_module_status.ps1` 
  - ⚠️ **严禁手工编辑**，所有数据通过脚本自动生成

### 📝 当前工作文档 (日常维护)
- **[当前工作状态](current-work-status.md)** - 近一周内的工作进展和当前状态
  - 🔄 **更新频率**: 每日更新，记录最新工作进展
  - 📅 **内容范围**: 当前正在进行的任务、本周完成的工作、下周计划
  - ⏰ **时效性**: 超过一周的内容会移动到季度历史文档

### 📚 历史工作文档 (长期存档)
- **[2025年Q4工作记录](work-history-2025-Q4.md)** - 2025年10-12月详细工作历史
- **[历史工作档案](work-history-archive.md)** - 长期历史工作记录
  - 📊 **组织方式**: 按季度和重大里程碑组织
  - 🎯 **用途**: 项目回顾、问题追溯、经验总结

### 🔧 专项跟踪文档
- **[问题跟踪](issues-tracking.md)** - 技术问题、解决方案、责任人跟踪
- **[自动化日志](automation_logs.md)** - 系统自动化操作记录
- **[状态目录说明](README.md)** - 本文档，说明文档结构和使用方法

## 🎯 使用说明

### 📋 日常工作流程
1. **每日开始** - 查看 `current-work-status.md` 了解当前任务状态
2. **工作进展** - 及时更新当前工作状态文档
3. **工作完成** - 将完成的工作移动到季度历史文档
4. **遇到问题** - 在 `issues-tracking.md` 中记录技术问题

### 🔄 文档维护周期
- **每日**: 更新 `current-work-status.md`
- **每周**: 整理当前工作状态，清理过期内容  
- **每月**: 更新季度历史文档，记录重大进展
- **每季度**: 创建新的季度工作历史文档

## 📊 自动化状态更新流程

### 模块开发完成时 (自动化)
```
模块编码完成 
    ↓
执行 tools/update_module_status.ps1
    ↓
自动更新 module-status.md (API数量、代码行数、完成率)
    ↓
在 current-work-status.md 记录完成情况
    ↓
一周后移动到 work-history-2025-Q4.md
```

### 工作历史管理流程
```
当前工作记录 (current-work-status.md)
    ↓ (超过1周)
季度历史文档 (work-history-2025-Q4.md)  
    ↓ (季度结束)
长期历史档案 (work-history-archive.md)
```

## � 强制规范

### ✅ 允许的操作
- 手工编辑 current-work-status.md 和 issues-tracking.md
- 执行自动化脚本更新 module-status.md  
- 阅读所有状态文档

### ❌ 禁止的操作  
- 手工编辑 module-status.md (只能通过脚本更新)
- 删除或重命名4个核心文档
- 添加新的状态文档 (保持简化结构)
- 跳过脚本直接修改模块统计数据
