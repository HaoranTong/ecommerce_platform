## 🎯 前端设计与开发所需信息清单（结构化）

> 目标：让 AI（或自动化工具）能**仅凭这些信息**，生成 100% 符合后端契约的前端页面。

### 一、**模块级元信息（Module Metadata）**

| 信息项   | 说明                                   | 来源示例                 |
| -------- | -------------------------------------- | ------------------------ |
| 模块名称 | 如 `product-catalog`                   | `design.md` 标题         |
| 模块路径 | API 前缀，如 `/api/v1/product-catalog` | `design.md` 接口设计     |
| 所属层级 | L1/L2/L3（影响权限/菜单）              | `design.md` labels       |
| 依赖模块 | 如依赖 `inventory-management`          | `design.md` dependencies |

------

### 二、**实体数据模型（Entity Schema）** ✅ **核心**

每个实体（如 Product, SKU）需要：

| 字段属性     | 说明                              | 来源                        |
| ------------ | --------------------------------- | --------------------------- |
| **实体名**   | 如 `SKU`                          | `models.py` 类名            |
| **表名**     | 如 `product_skus`                 | `__tablename__`             |
| **字段列表** | 包含以下子属性：                  | `Column(...)` 定义          |
| – 字段名     | `sku_code`                        | Column 名称                 |
| – 类型       | `String(100)`, `DECIMAL(10,2)`    | SQLAlchemy 类型             |
| – 是否主键   | 是/否                             | `primary_key=True`          |
| – 是否外键   | 是/否 + 关联表                    | `ForeignKey("products.id")` |
| – 是否必填   | `nullable=False` → 必填           | Column 参数                 |
| – 默认值     | `default=0`, `server_default=...` | Column 参数                 |
| – 唯一性     | `unique=True` 或 UniqueIndex      | Column / `__table_args__`   |
| – 注释/示例  | `comment="SKU编码: SKU12345"`     | Column 注释                 |
| **关系定义** | 一对多、多对一等                  | `relationship(...)`         |
| **软删除**   | 是否支持软删除                    | 是否继承 `SoftDeleteMixin`  |
| **索引信息** | 用于分页/排序建议                 | `__table_args__` 中的 Index |

> 💡 **关键**：这些信息**完全可从 `models.py` 静态分析提取**，无需人工干预。

### 三、**API 接口契约（OpenAPI Contract）**

| 信息项        | 说明                         | 来源                  |
| ------------- | ---------------------------- | --------------------- |
| 路径          | `/products`, `/skus/{id}`    | FastAPI 路由          |
| 方法          | GET/POST/PUT/DELETE          | 路由装饰器            |
| 请求体 Schema | 创建/更新时的字段规则        | Pydantic `schemas.py` |
| 响应体 Schema | 返回的数据结构               | Pydantic `schemas.py` |
| 分页参数      | `page`, `page_size` 是否支持 | 接口实现              |
| 权限要求      | 需要 `admin` 角色？          | `dependencies.py`     |

> ✅ **FastAPI 自动生成 `/openapi.json`，这是标准机器可读契约**。

------

### 四、**UI/UX 约束（来自设计标准）**

| 信息项       | 说明                                   | 来源                             |
| ------------ | -------------------------------------- | -------------------------------- |
| 字段显示名   | “sku_code” → “SKU编码”                 | 需要 i18n 或注释映射             |
| 字段组件类型 | 文本、数字、开关、下拉、日期等         | 基于字段类型 + 业务语义推断      |
| 下拉数据源   | `brand_id` → 需调用 `/brands` 获取选项 | 外键关系 + API 路径推断          |
| 树形结构     | `Category` 支持父子级 → 用 TreeSelect  | 自引用外键 (`parent_id`)         |
| 只读字段     | 如 `created_at` 不可编辑               | 时间戳字段通常只读               |
| 必填标识     | 表单中标红星                           | `nullable=False`                 |
| 输入校验规则 | 长度、格式、范围                       | Pydantic Validator / Column 约束 |

> ⚠️ 这部分目前**缺乏机器可读标准**，需补充（见后文建议）。

------

### 五、**业务规则（来自设计文档）**

| 规则类型       | 示例                                       | 来源                      |
| -------------- | ------------------------------------------ | ------------------------- |
| **字段排除**   | “SKU 不包含库存字段”                       | `design.md` 关键决策      |
| **跨模块调用** | “商品详情需合并库存数据”                   | `design.md` 架构图        |
| **状态机**     | `status` 只能是 `draft/published/archived` | `models.py` 注释 / Enum   |
| **默认行为**   | 新商品默认 `status=draft`                  | `Column(default="draft")` |

> 📌 这些是**防止前端犯错的关键**，必须结构化。

## 🔧 如何自动化提供这些信息？

| ------------ | ------------------------------------------------------------ |

| **UI 约束**  | 在 `models.py` 或 `schemas.py` 中添加 **结构化注解**（见下文） |
| **业务规则** | 在 `design.md` 中使用 **机器可读标记**（如 YAML frontmatter） |

## ✨ 建议：增强代码/文档的“AI 友好性”

### 1. **在 Pydantic Schema 中添加 UI 注解**

```python
class SKUSchema(BaseModel):
    sku_code: str = Field(
        ...,
        title="SKU编码",          # ← 前端显示名
        ui_type="text",           # ← 组件类型
        max_length=100,
        description="唯一商品编码，如 SKU12345"
    )
    price: Decimal = Field(
        ...,
        title="售价",
        ui_type="currency",       # ← 特殊组件
        ge=0
    )
    is_active: bool = Field(
        default=True,
        title="启用状态",
        ui_type="switch"          # ← 用开关代替 checkbox
    )
```

### 2. **在 design.md 中添加机器可读区块**
