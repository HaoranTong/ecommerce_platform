# 前端架构设计文档

## 1. 整体架构模式

### 1.1 多端分离与代码复用策略

**采用"核心共享 + 界面分离"策略**

基于本项目实际情况（已完成4个模块，21.1%完成度，采用文档驱动开发模式），我们不推荐完全的代码复用或完全的分离，而是采用**核心共享 + 界面分离**的混合策略：

- **核心共享层**：共享API定义、业务逻辑、工具函数、认证逻辑等
- **界面分离层**：各端独立实现UI和交互逻辑

**理由**：

1. 从后端文档(`docs/standards/naming-conventions-standards.md`)可见，项目已建立严格的命名规范和文档驱动开发模式，前端应继承这一理念
2. 管理后台与小程序功能差异大（管理后台需复杂数据操作，小程序需轻量交互），完全复用代码会增加复杂度
3. 但认证流程、API调用、核心业务逻辑（如分销关系）高度一致，重复实现会增加维护成本
4. 项目团队规模适中，需要平衡开发效率与维护成本

### 1.2 各端技术栈选型

#### 管理后台 (frontend-admin)

- **框架**: Vue 3 (Composition API)
- **理由**:
  - 与项目后端架构风格一致（清晰的分层、类型安全）
  - 团队已熟悉TypeScript（从Pydantic模型使用可见）
  - Vue 3的Composition API更适合复杂业务逻辑封装
  - 比React更适合快速开发管理后台（Naive UI组件库更成熟）

#### 消费者小程序 (mini-program-consumer)

- **框架**: Taro 3 + Vue 3
- **理由**:
  - Taro支持多端编译（微信/支付宝/百度等），为未来扩展预留空间
  - 使用Vue 3语法保持与管理后台技术栈一致性
  - 比uni-app更适合TypeScript项目（与后端Pydantic模型对接更顺畅）
  - 支持使用Vite构建，与管理后台构建工具一致

#### 分销代理小程序 (mini-program-agent)

- **框架**: Taro 3 + Vue 3（与消费者小程序相同）
- **理由**:
  - 代理端与消费者端大部分UI和交互相似，仅业务流程不同
  - 共享90%+的UI组件和工具函数，减少重复开发
  - 保持技术栈统一，降低团队学习成本

### 2.2 代码共享策略

#### 共享内容

| 类型     | 共享位置                     | 说明                     |
| :------- | :--------------------------- | :----------------------- |
| API类型  | `packages/core/api/types.ts` | 从后端Pydantic模型生成   |
| 认证逻辑 | `packages/core/auth`         | 处理JWT、角色区分        |
| 工具函数 | `packages/core/utils`        | 日期格式化、金额处理等   |
| 业务逻辑 | `packages/core/business`     | 分销关系绑定、商品验证等 |
| 业务组件 | `packages/components`        | 地理标志商品展示等       |

#### 共享方式

- **TypeScript类型**: 通过`packages/core/api/types.ts`集中管理，各端导入使用
- **业务逻辑**: 封装为纯函数，无UI依赖，可直接在各端调用
- **业务组件**: 使用Vue 3 Composition API编写，通过props适配不同端

**关键设计**：

1. 所有共享代码必须使用TypeScript编写，无任何平台特定API
2. 组件设计遵循"props驱动"原则，不依赖特定UI框架
3. 使用`process.env.TARGET`区分构建目标，避免条件编译

## 3. 核心技术栈

### 3.1 框架选择

| 组件       | 选型                    | 理由                                                         |
| :--------- | :---------------------- | :----------------------------------------------------------- |
| 基础框架   | Vue 3 (Composition API) | 与后端架构理念一致（清晰分层、类型安全），比React更适合管理后台开发 |

### 3.2 UI库选择

| 端       | UI库                | 理由                                                       |
| :------- | :------------------ | :--------------------------------------------------------- |
| 管理后台 | Naive UI            | 完整TypeScript支持，主题可定制性强，组件丰富度适合管理后台 |
| 小程序   | Vant 4 + 自定义组件 | 微信小程序生态成熟，轻量级，符合农产品平台简约风格需求     |

1. 项目已完成21.1%，需要快速推进前端开发

3. 通过主题定制可实现品牌一致性

### 3.3 类型系统约定

- **严格TypeScript**：所有代码必须使用TypeScript，noImplicitAny: true
- **接口命名**：采用PascalCase，以`I`为前缀（`IProductDetail`）
- **变量命名**：遵循后端命名规范（camelCase，参考[naming-conventions-standards.md](javascript:void(0))）
- **API类型同步**：通过自动化脚本从后端Pydantic模型生成TypeScript接口

## 4. 与 FastAPI 后端的集成方式

### 4.1 Pydantic 模型同步机制

**实现方案**：使用`pydantic-to-typescript`工具自动化同步

**工作流程**：

1. 后端开发完成后，运行`npm run generate:types`（在后端项目中）
2. 该命令调用`pydantic-to-typescript`，将Pydantic模型转换为TypeScript接口
3. 生成的类型文件自动复制到前端`packages/core/api/types.ts`
4. 前端开发时直接导入使用，确保类型一致性

**优势**：

- 避免手动维护类型定义，减少错误
- 符合项目文档驱动开发理念
- 与后端测试体系（Pydantic验证）无缝衔接

### 4.2 API 调用封装规范

```
typescript// packages/core/api/client.ts
import axios, { AxiosInstance, AxiosRequestConfig, AxiosResponse } from 'axios';

// 基于项目后端JWT认证机制设计
const createApiClient = (baseURL: string): AxiosInstance => {
  const instance = axios.create({
    baseURL,
    timeout: 10000,
    headers: {
      'Content-Type': 'application/json',
    },
  });

  // 请求拦截器：添加JWT令牌
  instance.interceptors.request.use(config => {
    const token = localStorage.getItem('access_token');
    if (token) {
      config.headers['Authorization'] = `Bearer ${token}`;
    }
    // 显示加载状态（各端自行实现）
    window.dispatchEvent(new Event('api-request-start'));
    return config;
  });

  // 响应拦截器：统一错误处理
  instance.interceptors.response.use(
    (response: AxiosResponse) => {
      window.dispatchEvent(new Event('api-request-end'));
      return response;
    },
    (error) => {
      window.dispatchEvent(new Event('api-request-end'));
      
      // 处理特定错误（基于后端统一错误响应格式）
      if (error.response) {
        const { status, data } = error.response;
        
        // 401 未授权：跳转登录
        if (status === 401) {
          localStorage.removeItem('access_token');
          localStorage.removeItem('refresh_token');
          window.location.href = '/login';
          return Promise.reject(new Error('未授权，请重新登录'));
        }
        
        // 403 禁止访问：根据角色显示不同提示
        if (status === 403) {
          const role = localStorage.getItem('role');
          if (role === 'agent' && data.detail === 'Requires admin role') {
            return Promise.reject(new Error('您没有权限执行此操作'));
          }
        }
      }
      
      return Promise.reject(error);
    }
  );

  return instance;
};

export const apiClient = createApiClient(import.meta.env.VITE_API_BASE_URL);
```

**封装原则**：

1. **统一错误处理**：基于后端返回的HTTP状态码和错误详情
2. **加载状态管理**：通过事件触发，各端自行实现UI反馈
3. **角色区分**：根据JWT中的角色信息处理不同权限的请求
4. **自动刷新令牌**：集成后端的refresh_token机制

### 4.3 JWT 鉴权与角色区分

**角色体系**：

- `customer`：普通消费者，可浏览商品、下单
- `agent`：分销代理，可查看分销数据、绑定下级
- `admin`：管理员，可管理商品、订单、用户

**实现方式**：

1. 登录成功后，将[role](javascript:void(0))信息存储在localStorage
2. 路由守卫根据角色控制页面访问权限
3. API调用时自动携带角色信息（JWT payload中已包含）
4. UI组件根据角色动态显示/隐藏功能

```
typescript// packages/core/auth/index.ts
export const getRole = (): 'customer' | 'agent' | 'admin' | null => {
  const token = localStorage.getItem('access_token');
  if (!token) return null;
  
  try {
    const payload = JSON.parse(atob(token.split('.')[1]));
    return payload.role || 'customer'; // 后端默认返回role字段
  } catch (e) {
    return null;
  }
};

// 路由守卫示例
export const requireRole = (roles: string[]) => {
  return async (to: any, from: any, next: any) => {
    const role = getRole();
    if (role && roles.includes(role)) {
      next();
    } else {
      next({ path: '/403', query: { redirect: to.fullPath } });
    }
  };
};
```

### 5.2 分销关系绑定实现

**业务流程**：

1. 代理生成专属推广链接/二维码
2. 消费者通过链接/扫码进入
3. 系统记录分销关系
4. 后续订单自动关联分销佣金

**技术实现**：

```
typescript// packages/core/business/distribution.ts
import { setCookie, getCookie } from '../utils/cookie';

/**
 * 初始化分销关系（在应用启动时调用）
 * 从URL参数或Cookie中获取分销ID
 */
export const initDistribution = () => {
  // 1. 从URL参数获取（优先级最高）
  const urlParams = new URLSearchParams(window.location.search);
  const agentIdFromUrl = urlParams.get('agent_id');
  
  if (agentIdFromUrl) {
    // 保存到Cookie，有效期7天
    setCookie('agent_id', agentIdFromUrl, 7);
    // 清除URL中的agent_id参数，避免分享时泄露
    const newUrl = new URL(window.location.href);
    newUrl.searchParams.delete('agent_id');
    window.history.replaceState({}, '', newUrl.toString());
    return;
  }
  
  // 2. 从Cookie获取（已访问过的用户）
  const agentIdFromCookie = getCookie('agent_id');
  if (agentIdFromCookie) {
    return;
  }
};

/**
 * 获取当前分销关系
 * @returns agent_id | null
 */
export const getCurrentAgentId = (): string | null => {
  return getCookie('agent_id');
};

/**
 * 生成推广链接
 * @param agentId 代理ID
 * @returns 推广链接
 */
export const generatePromotionLink = (agentId: string): string => {
  const baseUrl = window.location.origin;
  return `${baseUrl}/product?agent_id=${agentId}`;
};
```

**小程序二维码实现**：

## 6. 工程化与协作规范

### 6.1 Git 分支策略

基于项目当前状态（已完成21.1%，采用文档驱动开发），采用**简化版GitFlow**：

```
main ────────────────┬───────────────▶ 生产环境
                     │
develop ─────────────┼───────────────▶ 预发布环境
                     │
feature/* ────────────┼───────────────▶ 功能开发
                     │
hotfix/* ─────────────┴──────────────▶ 紧急修复
```

**具体规则**：

1. [main](javascript:void(0))：只接受来自`develop`的合并，对应生产环境
2. `develop`：每日构建，对应预发布环境
3. `feature/*`：功能分支，命名与后端模块一致（如`feature/product-catalog`）
4. `hotfix/*`：紧急修复分支，直接合并到[main](javascript:void(0))和`develop`

**特别说明**：与后端保持一致的分支命名规范，便于跨团队协作

### 6.2 提交信息规范

采用**Conventional Commits**，与后端规范保持一致：

```
<type>(<scope>): <short summary>
<BLANK LINE>
<detailed description>
```

**类型(type)定义**：

- `feat`: 新功能
- `fix`: Bug修复
- `docs`: 文档变更
- `style`: 代码格式调整（不影响功能）
- `refactor`: 代码重构
- `test`: 测试相关
- `chore`: 构建或辅助工具变更

**范围(scope)定义**：

- `admin`: 管理后台
- `consumer`: 消费者小程序
- `agent`: 代理小程序
- `core`: 共享代码
- `types`: 类型定义

**示例**：

```
feat(admin): 添加商品管理页面

- 实现商品列表展示功能
- 添加搜索和筛选功能
- 与后端product-catalog模块集成

```

## 7. SaaS 化预留设计

### 7.1 多租户支持设计

**实现策略**：基于域名的多租户识别

**技术方案**：

1. **租户识别**：

   ```
   typescript// packages/core/auth/tenant.ts
   export const getCurrentTenant = (): string => {
     const hostname = window.location.hostname;
     // 从域名提取租户ID（如 tenant1.platform.com）
     const match = hostname.match(/^(?:www\.)?([a-z0-9\-]+)\.platform\.com$/);
     return match ? match[1] : 'default';
   };
   ```

2. **API请求拦截**：

   ```
   typescript// 修改API客户端，自动添加租户ID
   instance.interceptors.request.use(config => {
     const tenantId = getCurrentTenant();
     config.headers['X-Tenant-ID'] = tenantId;
     return config;
   });
   ```

3. **后端适配**：

   - 在FastAPI中间件中解析`X-Tenant-ID`
   - 动态切换数据库连接或添加租户过滤条件

### 7.2 动态主题实现

**设计目标**：支持不同租户自定义品牌样式

**实现方案**：

```
typescript// packages/theme/index.ts
import { ref } from 'vue';

// 默认主题
const defaultTheme = {
  primaryColor: '#4CAF50',
  secondaryColor: '#8BC34A',
  logoUrl: '/logos/default.png',
  favicon: '/favicons/default.ico'
};

// 当前主题
export const currentTheme = ref({ ...defaultTheme });

// 从后端获取租户主题配置
export const loadTenantTheme = async () => {
  try {
    const tenantId = getCurrentTenant();
    const response = await apiClient.get(`/tenant/${tenantId}/theme`);
    
    // 合并主题配置
    currentTheme.value = {
      ...defaultTheme,
      ...response.data
    };
    
    // 更新CSS变量
    updateCssVariables(currentTheme.value);
    
    // 更新favicon
    if (response.data.favicon) {
      updateFavicon(response.data.favicon);
    }
  } catch (error) {
    console.error('加载主题失败', error);
  }
};

// 更新CSS变量
const updateCssVariables = (theme: any) => {
  document.documentElement.style.setProperty('--primary-color', theme.primaryColor);
  document.documentElement.style.setProperty('--secondary-color', theme.secondaryColor);
};

// 更新favicon
const updateFavicon = (url: string) => {
  let link = document.querySelector("link[rel*='icon']") as HTMLLinkElement;
  if (!link) {
    link = document.createElement('link');
    link.type = 'image/x-icon';
    link.rel = 'shortcut icon';
    document.getElementsByTagName('head')[0].appendChild(link);
  }
  link.href = url;
};
```

**主题配置存储**：

- 租户主题信息存储在后端`tenant`模块
- 包含：主色、次色、Logo、Favicon、自定义CSS
- 管理后台提供主题配置界面
